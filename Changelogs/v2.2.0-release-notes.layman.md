# pfind 2.2.0 — runs on Windows, and finds code it used to miss

**Date:** 2026-09-29

---

## Why This Release Exists

pfind finds files on your computer by name, by what is inside them, or by a piece of code you remember. Until this release it was built and tested on one Linux laptop. On 29 September 2026 we ran it on a Windows 11 laptop and it failed in ways a person would not notice: a file with an emoji in it stopped the search, a piece of code copied from a Windows file was never found, and without the helper program `ripgrep` it searched hidden folders and binary files. We also found a fault that affects everyone: pfind skipped every folder named `build` or `dist`, so it told you code did not exist when it did. This release fixes all of that, and adds a check-up command, `pfind --doctor`, that tells you what your computer is missing and offers to install it.

## What You Will Notice

**Code inside a folder named `build` or `dist`**
- Before: pfind skipped these folders completely. Searching for a function listed only the test that uses it, not the file that defines it.
- After:  pfind searches these folders. Build output that a project lists in `.gitignore` is still skipped when `ripgrep` is installed.
- Affects: everyone

**Pasting a piece of code to find it**
- Before: A snippet copied from a file saved on Windows (with Windows line endings) was never found.
- After:  The snippet is found whether the file uses Windows or Linux line endings.
- Affects: Windows users, and anyone searching files that came from Windows

**Files that contain emoji or other languages**
- Before: On Windows, one such file made the search stop with an error.
- After:  Any text prints safely, even on the old Windows console.
- Affects: Windows users

**Searching without `ripgrep` installed**
- Before: pfind searched hidden folders and binary files, ignored `--ext py` written without the dot, treated upper and lower case differently from the normal engine, and could not find multi-line snippets at all.
- After:  The built-in engine gives the same results as the `ripgrep` engine. It is slower and does not read `.gitignore`.
- Affects: anyone without `ripgrep`, which is most Windows users

**Searching for a word that is part of your own folder names**
- Before: Searching for "documents" matched every file under `C:\Users\...\Documents`, because pfind compared the word with the full path.
- After:  pfind compares the word only with the part of the path inside the folder you search.
- Affects: everyone

**Setting pfind up**
- Before: You had to read the code to find out what pfind needs. The shortcuts `--brain`, `--work` and `--src` pointed at folders on one laptop.
- After:  `pfind --doctor` checks your computer, names what is missing, and offers to install `ripgrep`. The shortcuts come from a small settings file you can edit.
- Affects: new users

## Deliberately Not Done

- **Installing anything without asking** — The doctor installs `ripgrep` only when you type `y`. When no one is at the keyboard, it prints the commands and stops.
- **Reading `.gitignore` in the built-in engine** — `ripgrep` does this correctly. Writing a second copy of those rules would give different answers in the two engines; the doctor points you to `ripgrep` instead.
- **A separate Windows version** — One file for both systems means a fix reaches everyone at once.

## Privacy & Security

pfind still makes no network connection when it searches. The only new network use is `pfind --doctor` installing `ripgrep`, and only after you type `y`; it uses your own package manager (winget, scoop, Chocolatey, apt, dnf, pacman, zypper or brew). pfind collects nothing and sends nothing. The new settings file, `presets.json`, holds only folder paths and stays on your computer.

## How to Install

**Before you start:**
- Python 3.8 or newer
- Optional: `ripgrep` for full speed (the doctor offers to install it)

**Step 1:** Download pfind, or update the copy you have.
```
git clone https://github.com/gorillanobakaa-dot/pfind.git   (or, in an existing copy: git pull)
```
✓ A `pfind` folder containing `pfind.py`, `pfind.cmd`, `README.md` and `tests`.

**Step 2:** Run the check-up and follow what it says.
```
python pfind.py --doctor   (on Windows: py pfind.py --doctor)
```
✓ Each line starts with [ok] or [--], and the last line says "Everything pfind needs is here." or lists install commands for `ripgrep`.

**Step 3:** Try a search in a folder you know.
```
python pfind.py something_you_know .
```
✓ A ranked list of files, best first, each with the lines that matched.

**Step 4:** On Windows, to type only `pfind` from any folder, add the pfind folder to your PATH.
✓ Typing `pfind --doctor` in a new terminal runs the check-up.

**To go back:** Go back to 2.1.0 with `git checkout bca6ac7 -- pfind.py` in the pfind folder, or download `pfind.py` from the 2.1.0 commit on GitHub.

## If Something Goes Wrong

**pfind is slow on a large folder.**
`ripgrep` is not installed, so pfind uses its built-in engine.
What to do: Run `pfind --doctor` and accept the install, or run one of the commands it prints.
Status: by design

**On Windows, `py` prints "Unable to create process".**
The Windows `py` launcher points at a Python that was removed, often from an old user account.
What to do: Use `pfind.cmd`, which falls back to `python`. `pfind --doctor` names the problem. Reinstalling Python repairs the launcher.
Status: detected in 2.2.0

**You see results from a folder named `build` that you do not want.**
pfind 2.2.0 searches `build` and `dist` folders because they often hold real code.
What to do: Add `--exclude build`, or list the folder in the project's `.gitignore`.
Status: by design

**A multi-line snippet cannot be typed in `cmd.exe`.**
`cmd.exe` does not accept line breaks inside an argument.
What to do: Save the snippet to a file and run `pfind --query-file snippet.txt -x`, or pipe it: `type snippet.txt | pfind - -x`.
Status: fixed in 2.2.0

## Common Questions

**Q: Is there a separate Windows download?**
A: No. The same `pfind.py` runs on Windows and Linux. Windows users can also use `pfind.cmd` to type `pfind` directly.

**Q: Do I need `ripgrep`?**
A: No. pfind works without it and gives the same results, more slowly and without `.gitignore` rules. `pfind --doctor` tells you how to install it.

**Q: Will I see more results than before?**
A: Yes, if your folders contain `build` or `dist` folders. Before, those were skipped completely.

**Q: Does the doctor change my computer?**
A: Only if you type `y` when it asks to install `ripgrep`. Otherwise it only reads and reports.

**Q: Can an AI coding assistant use pfind?**
A: Yes. `--json` gives results in a fixed, machine-readable shape, and `--query-file` passes code snippets without quoting problems.

## Bottom Line

pfind now does the same job on Windows as on Linux, and it no longer hides code that sits in folders named `build` or `dist`. We added 27 tests that check every behaviour on both search engines; without `ripgrep`, version 2.1.0 fails 10 of the 12 built-in-engine checks and 2.2.0 passes all of them. We tested 2.2.0 on Windows 11 only; the tests are written to run on Linux, but no one has run them there yet. If something behaves differently on Linux, it goes into a 2.2.1. If you use pfind on Linux, the change you are most likely to notice is extra results from `build` and `dist` folders.
