# pfind 3.3.0: one pfind again

**Date:** 2026-10-20

---

## Why This Release Exists

There were two pfinds. This repository had version 2.2, which made pfind work on Windows. Gorilla OpenCode carried version 3.2, a much bigger pfind that also draws folder trees, detailed file lists and line counts, and understands most of ripgrep's options. Each had things the other lacked: run against the 2.2 tests, the 3.2 engine failed 15 of 29. Version 3.3.0 is both in one file. The same file now ships here and inside Gorilla OpenCode, so a fix reaches everyone at once.

## What You Will Notice

**Looking around a folder**
- Before: pfind 2.2 needed a search word. Without one it stopped with an error.
- After:  Without a search word, pfind lists the folder: `--tree`, `--long` (sizes, dates, git status) or `--code` (lines of code per language).
- Affects: everyone

**Many more options**
- Before: 29 options.
- After:  183 options, including most of ripgrep's (context lines, file types, globs, counting, archives) and eza's listing options. `pfind --help` lists them all.
- Affects: people who already know ripgrep or eza

**Everything 2.2 fixed still works**
- Code in `build` and `dist` folders is found; pasted snippets match Windows line endings; emoji print safely on the old Windows console; `--doctor`, `--json`, `--query-file` and `-` for stdin all work; the built-in engine gives the same results as the ripgrep one.
- Affects: everyone, especially Windows users

**The tree view**
- Before: In 3.2, `pfind --tree` started at the drive and printed one line for every folder above the one you searched, including your user name.
- After:  The tree starts at the folder you searched.
- Affects: anyone using `--tree`

**Semantic search (`--brain`)**
- Before: The README said the model is downloaded once from the internet.
- After:  `--brain` downloads nothing and sends nothing. The model must already be on your computer.
- Affects: `--brain` users

## Deliberately Not Done

- **Keeping 2.2's error for a missing search word** — 3.x uses "no search word" to mean "list the folder", and Gorilla OpenCode relies on it. An empty `--query-file` or empty stdin is still an error.
- **A default location for the brain database** — 2.2 guessed one inside the brain folder. 3.3 does not guess: you set it in `presets.json` or with `PFIND_CHROMA`.

## Privacy & Security

pfind makes no network connection when it searches. `--brain` opens Chroma with its usage reporting cut out and its model download refused; a test proves it on a real Chroma behind a dead proxy. The only network use is `pfind --doctor` installing ripgrep, and only after you type `y`.

## How to Install

**Before you start:**
- Python 3.7 or newer
- Optional: `ripgrep` for full speed (the doctor offers to install it)

**Step 1:** Update your copy.
```
git pull
```
✓ The first lines of `pfind.py` say `VERSION: 3.3.0`.

**Step 2:** Run the check-up.
```
python pfind.py --doctor
```
✓ Each line starts with [ok] or [--].

**Step 3:** Try it.
```
python pfind.py --tree
```
✓ The current folder as a tree, starting with the folder's own path.

**To go back:** `git checkout 5da5fe4 -- pfind.py` restores 2.2.2.

## If Something Goes Wrong

**`pfind` with no search word lists files instead of saying a query is needed.**
That is the 3.x behavior.
What to do: Give a search word, or use `--query-file` / `-`.
Status: by design

**`--brain` says no Chroma store is configured.**
3.3 does not guess where the database is.
What to do: Add `"chroma": "path/to/chroma_db"` to `presets.json`, or set `PFIND_CHROMA`.
Status: by design

## Bottom Line

One pfind again: 2.2's Windows work and 3.2's extra features in one file. All 33 tests pass on Windows 11 with ripgrep and on the built-in engine, and Gorilla OpenCode's own find tests pass with this file. It has not yet been run on Linux or macOS in this form.
