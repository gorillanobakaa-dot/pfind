# pfind 3.3.0: the 2.2 (standalone) and 3.2 (Gorilla OpenCode) lines merged
**Date:** 2026-10-20

---

## Summary

Two lines had diverged. Standalone 2.2.x (this repository, 949 lines, 2026-09-29 Windows port) and 3.2.0 (embedded in Gorilla OpenCode as `internal/llm/tools/pfind.py`, 3291 lines, a rewrite carrying ripgrep 15.2.0 and eza 0.23.5 flag surfaces). The 3.2 engine against the 2.2 test suite: 15 of 29 cases failed with ripgrep present, and 9 of 16 without it. Base for the merge: 3.2 (it is the larger feature set and the one Gorilla OpenCode tests against). The 2.2 features were ported into it. Result: 3.3.0, 3605 lines, 183 options (2.2 had 29), one file for both places.

## Code Changes

| Area | 3.2 behavior | 3.3 behavior |
|------|--------------|--------------|
| `EXCLUDE_GLOBS` | contained `build`, `dist` | removed (they hid real source); `obj-*` and `.gitignore` still skip build output |
| ripgrep subprocess | `text=True`, locale code page | `_rg_run()`: `encoding="utf-8", errors="replace"` |
| snippet mode (`-x`, pasted block) | `rg -F -U` with the raw query; built-in engine line-based, so a multi-line snippet never matched there | `build_exact_regex()`: escaped lines joined with `\r?\n`; built-in engine matches multi-line patterns against the whole file (`re.DOTALL`, line numbers via `bisect`) |
| `py_fallback_files` | folder-name excludes only; `--ext` compared raw | every `EXCLUDE_GLOBS` pattern via `fnmatch` on folders and files; `_norm_exts()` accepts `py` or `.py` |
| `py_fallback_content` case | case-sensitive unless `-i` | `_smart_insensitive()`: ripgrep precedence `-s` > `-i` > smart case; escapes ignored when looking for capitals |
| coverage terms (built-in) | `{pattern}` | distinct matched substrings, as the rg path records |
| `match_names` | scored the absolute path; case-sensitive unless `-i`/`--fuzzy` | `_inside()` scores the path relative to its root; smart case |
| samples | multi-line block printed raw, `\r` kept | `_sample()`: CRLF-safe, multi-line folded with `↵`, cut at 220 |
| query input | positional only | `--query-file FILE`, or `-` reads stdin; an empty one exits 2 "a query is needed" |
| output | text only | `--json`: `{engine, matched, results: [{path, score, why, hits, samples: [{line, text}]}]}`; exit 1 with `results: []` |
| setup | none | `--doctor` (`--doctor --json`): Python, ripgrep, git, console, presets file, `py` launcher, chromadb; installs ripgrep only on an interactive `y` |
| colour on Windows | `isatty()` | `setup_console()`: VT processing through `SetConsoleMode`, or no colour |
| presets | read at import from `$XDG_CONFIG_HOME/pfind/presets.json` | read in `main()` (`load_presets()`); `%APPDATA%\pfind\presets.json` first on Windows when present; `expandvars`; `PFIND_BRAIN_DB` alias of `PFIND_CHROMA`; a malformed file is reported, not ignored |
| `--tree` | trie built from absolute path parts: drive, then one line per folder above the root | starts at the single search root (or the deepest common folder); `args._roots` set in `main()` |
| `--brain` | Chroma doors cut (`_cut_chroma_doors`, from Gorilla OpenCode) | unchanged |

Kept from 3.x over 2.2: no query means exploratory listing (2.2 exited 2). Gorilla OpenCode's `find` tool calls `--tree`, `--long` and `--code` without a query.
