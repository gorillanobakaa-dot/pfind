# pfind 2.2.0: Windows port, engine parity, build/dist no longer excluded, --doctor, --json, --query-file
**Date:** 2026-09-29

---

## Summary

Root causes, as found on Windows 11 on 2026-09-29. (1) `subprocess.run(..., text=True)` decodes ripgrep's UTF-8 output with the locale code page (cp1252); an emoji produces an undecodable byte, the reader thread fails, `proc.stdout` is `None`, and `rg_content` raises `AttributeError`. (2) Snippet mode passes the query to `rg -F -U`; a snippet with `\n` never matches a file with `\r\n`. (3) `py_fallback_files` applied only folder-name excludes and ignored hidden entries and file-name globs; `py_fallback_content` was line-based, case-sensitive unless `-i`, did not skip binaries, and compared `Path(fn).suffix` with a raw `--ext` value. (4) `EXCLUDE_GLOBS` contained `build` and `dist`, which ripgrep applies to any path component, so `fieldkit/build/kernel.py` was invisible. (5) `match_names` scored substrings of the absolute path, so a query that matches part of the search root matched every file. Fix approach: `_rg_run()` decodes UTF-8 with `errors=replace`; `setup_console()` reconfigures stdout/stderr and enables VT processing through `SetConsoleMode` on Windows; `build_exact_regex()` turns a literal snippet into a regex whose line breaks are `\r?\n`; the fallback is rewritten for parity with the rg path; `build` and `dist` are removed from the excludes; `_inside()` scores the path relative to its root. New: `--doctor`, `--json`, `--query-file`, `-` (stdin), `presets.json`, `PFIND_NO_RG`, `PFIND_BRAIN_DB`, `pfind.cmd`. Scope: `pfind.py` 607 -> 883 lines, 28018 -> 41414 bytes; `README.md`; new `pfind.cmd`; new `tests/test_pfind.py`.

Other alternatives: Not available in the source material.

## Architecture Impact

pfind remains one file with only the standard library for the core. The two engines are now required to be equivalent, and the test suite enforces this by running every behaviour against both (`PFIND_NO_RG=1` selects the built-in engine). Machine-specific constants (`MACHINE`, `LOGICAL_CPUS = 8`) are gone; presets load from `presets.json` in `%APPDATA%\pfind\` or `$XDG_CONFIG_HOME/pfind/` (default `~/.config/pfind/`). Snippet mode now always runs as a regex (`build_exact_regex` or `build_loose_regex`).

## Known Issues

**[low]** More results than before in trees with `build/` or `dist/`
- Cause: Those folders are no longer excluded by default
- Remedy: `--exclude build dist`, or list them in `.gitignore`

**[low]** Built-in engine returns files that ripgrep would skip
- Cause: The built-in engine does not read `.gitignore`
- Remedy: Install ripgrep (`pfind --doctor`) or use `--exclude`

**[low]** `py` fails with "Unable to create process" on Windows
- Cause: The `py` launcher points at a removed Python installation
- Remedy: Use `pfind.cmd` (falls back to `python`); reinstall Python to repair `py`

**[medium]** Behaviour differs on Linux (deferred to 2.2.1)
- Cause: 2.2.0 is verified on Windows 11 only
- Remedy: Run `python -m pytest -q tests` on Linux and report failures
